# 垄上 · CKB 链上农场

一个完全跑在 [Nervos CKB](https://www.nervos.org/) 上的种菜、偷菜游戏。开垦、播种、除草除虫浇水、收获、卖菜、扩地、养狗，以及去邻居地里摘菜、帮忙、放草放虫，全部由一份链上合约验算。没有服务器；存档和判定都在链上，当前规则下谁也不能单方面动你的农场。合约**可以由部署者公开升级**（见下文"升级与信任模型"）：升级换的是规则代码，type id 不变、每一次升级链上可查；但升级权是真实的权力，玩之前请读那一节。

**已审计（四份模型审计汇总）**：统一基线见 [AUDIT.md](AUDIT.md)，原始报告包括 [AUDIT-gemini-4-neon.md](AUDIT-gemini-4-neon.md)（Gemini 4 Neon，2026-11-23 最新）、[AUDIT-qwen4-max.md](AUDIT-qwen4-max.md)（qwen4-max，四轮）、[AUDIT-fable-5.2.md](AUDIT-fable-5.2.md)（Claude Fable 5.2）与 [AUDIT-glm-5.3-flash.md](AUDIT-glm-5.3-flash.md)（glm-5.3-flash）。方法涵盖源码逐行审查 + 真实 CKB-VM 攻击探针 + 本地链/测试网实链验证；**69 个测试**在当前二进制上全部通过。审计发现的高危漏洞（小费关闭他人农场）及全部三项中危问题（历史区块头按天步进重置计数、同笔放草拔草零状态变化活性 DoS、`shutdown.ts` 跨 `unit` 漏检）**均已修复并在本地链与测试网上线**；ACP / OmniLock-ACP 强关风险（GN-01）已在官方前端禁止开垦缓解。核心遗留：部署钥匙仍是单把热钥匙、使坏上限按农场计（低危）。**没有部署到主网**；这些是模型审计，不等同第三方审计公司。

玩法是经典的社交农场那一类，但这是一个原创游戏：名字、美术、数值和界面都是这个项目自己的，没有使用任何现成游戏的素材。

## 一分钟跑起来

需要 Node 20+，以及 [offckb](https://github.com/ckb-devrel/offckb)（只用它下载的 `ckb` 节点程序；也可以用 `CKB_BIN=/path/to/ckb` 指定）。

```bash
./start.sh
```

它会依次：启动项目自带的本地链（`127.0.0.1:8214`）、部署合约、放出 4 个自己种地也会串门的邻居机器人、启动网页。然后打开 <http://localhost:5183>，右上角选一个测试账户，开垦农场。

本地链上 1 个游戏小时是 30 秒，萝卜 1 分钟就熟。

```bash
./start.sh stop
```

停掉本地链和机器人。`scripts/devnet.sh reset` 清空本地链重新开始。

## 为什么说它是去中心化的

| 通常由服务器做的事 | 这里怎么做 |
| --- | --- |
| 保存存档 | 每座农场是一个 CKB cell，状态（金币、经验、土地、仓库、每块地）就是 cell 的数据 |
| 判定操作是否合法 | 农场 cell 的 type script 重放交易里的操作列表，算出的新状态必须和交易输出逐字节相同 |
| 账号 | 农场记着主人的 lock hash。花金币的操作要求交易里有主人的 cell，也就是主人的签名 |
| 好友系统 | 没有。同一条链上的农场都是邻居，谁都可以去 |
| 计时 | 取自区块头的时间戳，见下文 |
| 随机（杂草、虫害、狗拦不拦） | 取自打包播种交易的那个区块的哈希 |
| 运营方绕过规则直接转走你 cell 里的 CKB | 当前规则下做不到。农场 cell 的 lock 是公开脚本，能做的事只有规则允许的那几样，cell 里押的 CKB 只增不减。但部署者可以升级成别的规则——见下一行和"升级与信任模型" |
| 运营方改规则 | 可以，且公开：代码 cell 用 type id 固定身份、由部署者的锁看守。升级 = 部署者花一次代码 cell 换上新二进制，type id 不变，所有农场原地运行新规则（见下文"升级与信任模型"）。改了什么、何时改的，链上全部可查 |

**把话说透**：升级权是一把真实的权力。持有部署私钥的人可以换上任意新规则——包括对老存档不利的规则，甚至销毁代码 cell 让所有农场永远冻住（CKB 取不回来）。type-id 校验器保证的是"升级不会漂移身份、没有第二份伪造代码"，**不是**"升级一定善意"。玩之前请认清这一点：这是一个规则公开、升级透明、但升级权集中在部署者手里的游戏。详见"升级与信任模型"。

网页只是一个方便的客户端。它用的规则代码和合约是同一份 Rust（编译成 WASM），所以页面上显示的"可以做什么"和链上的判定不会不一致。任何人都可以另写一个客户端，或者直接构造交易。

### 一笔交易长什么样

```
inputs                          outputs
  [0] 我的农场  ──操作列表──▶    [0] 我的农场（新状态）
  [1] 邻居的农场 ─我的来访──▶    [1] 邻居的农场（新状态）
  [2] 我的普通 cell（付手续费，     [2] 找零
      同时证明我是 [0] 的主人）
header_deps: 两座农场各自所在的区块、一个最近的区块（证明"现在至少是几点"）
```

- 农场 cell 的 lock 也是这份合约，逻辑只有一条："这个 cell 必须带着农场 type script"。所以邻居不需要你的签名就能把你的农场放进交易，但能对它做的事只有规则允许的那几样（摘熟了的菜、帮忙、放草放虫），并且 cell 里押的 CKB 只增不减。
- 来访操作写在被访农场的 witness 里，指明访客是第几个输入。访客农场的脚本会重放同一份列表，把摘到的菜和帮忙的经验记到自己账上。两边各算各的，结果必须对得上。
- 一笔交易可以放很多操作。网页把你点的操作攒在篮子里，一次上链。

### 时间

合约没法知道"现在几点"，只能知道"某个区块存在，所以现在至少是它的时间"。因此：

- 交易带一个最近的区块头，它的时间戳就是这笔交易的"现在"。只能往早了报，报早了作物只会更不熟，没有好处。
- 播种时不记时间。下一次有人动这座农场时，合约读取"播种那笔交易所在区块"的时间戳和哈希，补记播种时刻并生成这块地的随机种子。播种的时间因此无法谎报。

- 升到第 n 级需要累计 `50 × n × (n − 1)` 点经验。
- 作物生长途中可能长草、生虫、缺水。收获时每留一样没处理，减产 10%。自己处理一次 2 点经验。
- 熟了的作物，每个邻居每季每块地能摘一次，每次摘走产量的 8%，所有邻居合计最多摘走 40%。
- 帮邻居处理一次问题得 3 点经验，每天前 50 次有效。每天最多使坏（放草或放虫）30 次。
- 3 级起可以花 300 金币喂狗，管一天（24 游戏小时）。狗站岗时，每个来访者在大约一半的地里会被拦下。
- 多季作物收完最后一季、单季作物收获后，会留下枯株，铲除得 3 点经验。
- 主人可以随时收回农场：cell 销毁，押着的约 332 CKB 回到钱包。


改了规则就重新构建合约和 WASM，然后原地升级：`npm run build`（合约）→ `bash scripts/build-wasm.sh`（前端 WASM）→ `npm run upgrade`。升级花一次代码 cell 换上新二进制，**type id 不变**，所有农场原地运行新规则，不用重新开垦。规则改动的同步要点：合约与前端 WASM 是同一份 Rust，必须一起重编译，否则前端算出的初始状态会被链上拒绝（例如改了 `INIT_GOLD` 而没重编 WASM，开垦会报"新农场必须从初始状态开始"）。

### 测试网

合约部署在 CKB 测试网上，采用**可升级的两 cell 结构**：

- **type-id 校验器 cell**：锁是全零哈希（永远打不开），代码 cell 的 type script 就是它。它保证代码 cell 的 type id 只此一份、升级时不会漂移。
- **代码 cell**：锁是部署者的锁，data 是农场二进制。农场 cell 用 `hash_type: "type"` 引用代码 cell 的 type script 哈希，所以升级后所有农场原地运行新代码。

当前版本：代码 cell 交易 `0xcb92cb0103c87b76d7be2a7cb2010eb36074c021339cd6417b0c39a9dc454df5`，引用哈希（code script hash）`0x0253fea2b3d45853c5381fb20ed7efffce8f79cfbb059e1ea3befddf299f775d`，版本哈希 `0x4e2dc6328519ad576cb9963f7693ae2a9b4ebc914c555bd5793975fd3a4055bf`，游戏时速 3600 秒/小时。2026-11-23 原地升级上线，包含 close 双条件修复、closing-visitor 守卫（错误码 54）、历史区块头按天步进防护（OPEN-03）及同笔放草拔草/零状态变化防护（OPEN-04），前端已同步构建发布至 Cloudflare Pages 并禁止 OmniLock-ACP / ACP 地址开垦（OPEN-01 缓解）。最新记录以 `web/src/chain/deployments.json` 为准。网页默认跑测试网；跑本地链则在 `web/.env` 里写 `VITE_NETWORK=devnet`。

测试网用 CCC 的钱包连接器登录：网页上是"连接钱包"按钮，支持 JoyID、MetaMask、OKX、UniSat 等。钱包需要有测试网 CKB（[水龙头](https://faucet.nervos.org/)）才能付手续费和创建农场 cell。本地链仍使用内置测试账户，不需要钱包。

代码 cell 约 49,000 CKB、校验器约 28,500 CKB。

**部署钥匙单独生成、永不进 git**：

```bash
cd web
npm run key:new -- deployer          # 生成 keys/deployer.key（0600，已 gitignore，拒绝覆盖）
npm run key:info -- deployer         # 地址与余额；去水龙头充值后部署
npm run build                        # 首次部署需要先构建合约
npx tsx scripts/deploy.ts --network testnet --keyfile keys/deployer.key
```

钥匙只从文件读（`--keyfile <路径>` 或环境变量 `FARM_KEYFILE`），不再接受 `--privkey`：命令行参数会留在 shell 历史里，也会出现在本机所有用户都能看到的进程列表里。钥匙文件权限必须是 600，否则脚本拒绝执行。

主网部署再加一道门：`--network mainnet --yes --keyfile …`，缺一不可。

**两个部署 cell 都是可回收的**（校验器默认由部署者的锁看守，加 `--immortal-validator` 可改回全零锁的永生模式）。关服流程：

```bash
cd web
npm run shutdown:testnet -- --keyfile keys/deployer.key    # 主网：--network mainnet --yes --keyfile …
```

脚本会拒绝在还有农场未关闭时执行（烧掉代码 cell 会把未关闭农场的押金永久冻结），把两笔容量——代码 cell 约 49,500 CKB、校验器约 28,400 CKB——全额退回部署者地址，并移除部署记录（站点随即显示"未部署"）。校验器若由私钥看守，持有者也能**搬移**它（同二进制换新 outpoint），引用按数据哈希解析、不受影响。

**升级**（改了规则之后）：

```bash
bash scripts/build-contract.sh && bash scripts/build-wasm.sh
cd web && npx tsx scripts/upgrade.ts --network testnet --keyfile keys/deployer.key
npm run build && npm run deploy:pages   # 前端记录更新后重新发布网页
```

### 升级与信任模型

代码 cell 的锁就是升级权限。这把私钥能做什么、不能做什么，逐条列清楚：

**能做的：**

- 换上任意新二进制。所有农场从下一笔交易起运行新规则，老存档原地生效。新规则可以对老存档不利（例如改数值、改判定），链上不会阻止。
- 销毁代码 cell（type-id 规则允许 burn）。后果是所有农场 cell 的 lock/type 失去可解析的代码，**永远无法再移动，押在里面的 CKB 也取不回来**。这是事实上的"关服开关"，虽然不能把别人的 CKB 转给自己，但能把它冻死。

**不能做的：**

- 伪造第二份代码 cell 或改掉 type id：type-id 校验器（锁死、不可升级）拒绝一切身份漂移，全网只有一份代码身份。
- 绕过农场规则直接转走农场 cell 里的 CKB：只要运行的还是这份农场二进制，容量只增不减、关闭必须主人在场。**但注意**——上一条"能换任意二进制"意味着部署者理论上可以换上一份允许转移 CKB 的规则。所以"不能偷 CKB"的前提是"部署者不换恶意规则"，这正是信任所在。

结论：**这是一个升级权集中、升级过程透明的游戏，不是"无人能改"的游戏。** 部署私钥等同于整个游戏的管理员密钥。当前测试网的部署私钥是脚本生成的测试钥匙（`.testnet-deployer.key`，只持有测试币）；**上主网前必须换成多签或硬件钱包，并公开升级治理方式**（例如时间锁、社区监督、或最终放弃升级权把代码 cell 锁死）。type-id 校验器保证升级"身份不漂移、无伪造副本"，不保证升级"善意"。

升级的链上验证（`tests/tests/upgrade.rs`，5 个测试跑在真实 CKB-VM 里）：代码 cell 不能复制、type id 不能漂移、伪造第二世界被拒、原地换代码后老农场照常验证、销毁代码 cell 后农场被冻结。本地链上做过完整往返：`INIT_GOLD` 500→600 升级生效、老农场在新规则下继续玩、再升回 500 新农场恢复 500，全程 type id 不变。
